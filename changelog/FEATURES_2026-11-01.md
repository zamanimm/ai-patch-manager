# AI Patch Manager — New Features (2026-11-01)

Based on `AI_Patch_Manager_Phase3_Diff_Color_Fixed.zip`; includes Phases 1–3 and the diff background color fix.

## Implemented

1. **Project → Open Folder**: open the current workspace directory in the OS file explorer. Disabled if no project folder exists.
2. **Changes → Clear Parsed Changes**: confirm and discard in-memory parsed changes, summaries and diff previews only. The raw Response XML, the workspace on disk, and applied transaction history remain untouched; Parse + Validate can regenerate changes from raw XML.
3. **Remember user sizing**: independently persist Project file-tree column widths, History tree column widths, the horizontal Changes and History splitters, the vertical Changes diff/editor split, and the window geometry/dock state. `QSettings` auto-saves user drags and saves again on close; restored on the next launch. All header columns can now be manually resized.
4. **Edit in Changes preview**: `Edit proposed code` checkbox reveals an editable code panel below the unified diff. The panel edits the `content` of create/replace/append/prepend proposals only. `Save & Validate` revalidates every proposed change and regenerates all diffs. An unsaved edit disables Apply/Dry Run. Navigating away auto-saves and revalidates; if validation fails, draft remains and Apply cannot proceed. Delete and Rename do not expose this code panel. Original file data is not changed by the editor.
5. **Double-click Changes list → external code editor**: the app asks for an editor executable on first use, remembers it via QSettings, and uses `OpenWith` to launch it with the existing project file path. Right-click → Choose another editor to change the preference. A missing/not-yet-created file shows a warning; the Python file association is never invoked automatically.
6. **Strict XML-only instructions**: every generated prompt includes a concise mandatory `<output_contract>` even when `include_system` is off. The Instructions tab and full system prompt state that the LLM must return one XML document only, with no questions, answers, commentary, duplicated text or Markdown. System instruction text and embedded example schemas are XML-escaped so the instructions are well-formed. A safe no-op `<status>no_changes</status><changes/>` is now accepted by the parser (a success document with no changes is still rejected).
7. **Project refresh fix**: `ProjectView.reload` now exists when returning to the Project tab, preventing an existing missing-method error.

## Known limitations / important safety

- This feature update intentionally does **not** change the patch engine. The earlier Phase 3 audit identified separate transaction-safety issues (undo/redo overwriting manual edits, backup collisions, binary rename corruption and rollback edge cases). Those remain to be addressed before treating the application as safe for irreplaceable projects.
- External editor selection is a manual user choice and opens the real on-disk file. Code changes made in that editor are separate from the proposed diff edits; revalidation is recommended before applying.
- Proposed-code edits in Changes are session-local, as they were previously with Ctrl+H replacement. To edit the raw XML permanently, use the Response tab and reparse.
- Layout state is per user/application, not per workspace; resizing remains normal Qt widget behavior.


## Follow-up update: optional project tree in prompt

- Added the **Project tree (paths only)** checkbox to the Prompt tab.
- Default is OFF; choice persists per workspace.
- Adds a hierarchical `<project_tree>` XML block with directory/file names only. No source file contents are read for this block.
- Independent from the `<files> content` checkbox.
- The tree is generated from the currently scanned project file list and honors include/exclude filters.
- Hardened path handling: absolute, drive-qualified, parent-traversal, and empty paths are ignored; XML attribute values are escaped.
- **Clear Parsed Changes** was already present in the Changes tab and remains unchanged; its existing confirmation and response/history preservation behavior is covered by tests.
